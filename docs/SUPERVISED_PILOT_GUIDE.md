# Quillora: supervised pilot guide

For 2–3 students, one 30–45 minute session each. Use the reviewed local build, one editing tab per student, and DOI-bearing journal articles only. Quillora supplies **draft citations**, not verified references. Nothing from this test should be submitted for a grade without independent checking.

## Before the session — facilitator

- Use Chrome or Edge on a controlled local computer. Record the exact browser and app commit. Keep the server on loopback; no hosting or public exposure is required. Different devices cannot use another computer's `127.0.0.1` address.
- Use a separate existing browser workspace for each student. Do not mix students' research in a shared storage space. Start with fictional assignment names and non-sensitive practice questions; no grades, names, accommodations or private rubric content.
- Export any existing work before testing. Never clear site storage or overwrite existing backups. Keep the original backup and a second private copy.
- Confirm the student's normal input and assistive technology works for creating an assignment, reading a citation, copying, and exporting. Spoken screen-reader acceptance and Firefox are not yet verified. If the student's required setup fails this check, postpone that session and record the barrier; do not substitute assistance for an accessibility pass.
- Have two journal articles ready with accessible publisher pages/full text and working DOIs. Avoid incomplete/corrupted metadata, ambiguous consortium bylines, books, chapters, and sources needing complex internal title typography.

## Student tasks

1. Create a fictional assignment. Enter a practice research question, choose **Save assignment details**, and wait for the saved confirmation. Search by article title or topic; a DOI entered in search is a query, not a guaranteed exact DOI lookup.
2. Open each original article via its DOI. Confirm the result is the intended journal article; Crossref does not establish quality, peer review, free access or support for your claim. Save two suitable sources to the assignment.
3. Generate APA, then MLA. Before using either, check every reference against the article and the required style guide: author names/order and group credit; complete title/subtitle; capitalization and nested quotes/italics; journal, volume, issue, date; page range versus article identifier; DOI. Check all warnings. Do not invent missing facts. Ask the facilitator when uncertain; omit an unreliable source from the pilot exercise.
4. Paste into your normal document editor. Compare the complete pasted text with the reviewed citation. Check italics, punctuation, author order and DOI. Plain-text fallback/manual copying requires italics to be reapplied. If copying fails, use the selected **Citation for manual copying** field and Ctrl+C/Command+C; verify the paste before continuing.
5. Use Tab, Shift+Tab and Enter through the main tasks. Check visible focus. Open a dialog, use Escape, and confirm focus returns to its opener. Record any unreachable control or confusing announcement. Do not change browser permissions or security settings to make the test pass.
6. Save assignment details and export a backup. Reload once and reopen **Assignments**. Confirm the question and both saved sources remain. Search results and citation-only title edits are temporary; title edits do not rewrite the saved article and are not included in backups.

## Backups and recovery

- At the start and after every session, click **Export backup** near the bottom. Wait for the browser download to finish. Rename the new file with the date and a non-identifying participant code; keep earlier versions. Open a copy as text and confirm it contains the expected assignment/source counts. Keep two private copies; JSON exports are unencrypted and do not contain article PDFs or document-editor files.
- Export includes **saved work only**. Wait for saves; unsaved assignment edits must be saved first. If saving fails, keep the tab open and export both **Export backup** and **Export attempted changes** where offered. For unreadable/conflicting storage, also use **Export stored data for recovery**. Never clear storage as a troubleshooting shortcut.
- If search fails, preserve the question, wait, and use **Retry search**. A session-verification error while offline requires restoring the connection and reopening the same local address/access context. Previously saved work should remain; unsaved work is not guaranteed and the app is not an offline editor.
- Restore only with the facilitator: preserve the current backup first, choose **Import backup**, inspect the preview/counts, then **Merge backup**. Wait for a saved confirmation. Import merges and may create separate conflicting assignment copies. It is not a replacement/rollback operation. Prefer a separate disposable workspace for a restore drill; never test recovery over irreplaceable work.

## Record and stop rules

Record participant code, app commit, browser/version, input/assistive technology, task pass/fail, DOI, expected versus actual behavior, and whether help was needed. Keep research content out of public issue reports.

Stop and preserve the tab/backups if saved data disappears, a save/export fails, citations silently change authors/DOI, a required control is inaccessible, or the student cannot verify a source. No grading decisions or real submissions should depend on this pilot.

Proceed beyond this small pilot only after reviewing all 2–3 sessions: every saved-work reload and backup must succeed; every used citation must be independently checked; unresolved access barriers or data loss are release blockers.
