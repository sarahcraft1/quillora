## Corrections implemented in this pass

1. Abort obsolete search/rubric requests on context changes; invalidate late results, reset loading and clear results when switching/creating/leaving assignments. Leaving an assignment no longer carries its rubric into unrelated work.
2. Reject empty/oversized rubric files client-side before transmission; reset the file input so the same file can be retried. Server bounds remain authoritative.
3. Disable unavailable peer-review/access filters instead of offering guaranteed-empty “verified” filtering. Explain the returned-record scope of working filters.
4. Add optional, backward-readable assignment notes and editable names. Preserve conflicting notes during import, with repeat-import deduplication. No existing store is rewritten automatically.
5. Warn about unsaved assignment edits before context changes or browser unload; offer Save and continue, explicit discard or Keep editing. A failed save preserves the old bytes and exposes attempted-change recovery. Unconfirmed rubric edits cannot silently erase saved requirements.
6. Make assignment removal unlink only that assignment. Retain intentional shelf-wide removal with a clear explanation.
7. Prevent New assignment from silently copying the active assignment; cancellation preserves the old project. The existing Save as assignment action explicitly preserves a draft as a separate project.
8. Fix modal name focus and keyboard focus restoration; add skip/focus/mobile containment without redesigning the application.
9. Expand citation regressions; replace a categorical MLA omission claim with an explicit review warning. Keep metadata, proper nouns, acronyms and verification status conservative.
10. Allow an explicitly selected loopback QA port for the disposable recovery harness; no production bypass or test route was added.

- Standalone TypeScript check, production build and the separate loopback production HTTP security smoke all passed. Local Windows validation is not a fresh Linux container certification.
- `npm audit --json`: **zero reported vulnerabilities**, including development dependencies, at this check. This is a registry advisory result, not proof that all code is vulnerability-free.
- Current tracked high-confidence private-key/token patterns: no findings. Existing repository regression checks confirm ignore exclusions and sanitized Markdown. No real student data was used; downloaded synthetic backups stayed outside Git. Historical disclosure remains accepted and unchanged; no history audit/rewrite was repeated.
- Live local endpoint checks passed PDF/DOCX, invalid PDF, unsupported file, missing file and query validation, plus three searches returning 24 records each with an individual Crossref record comparison. Frozen tests use real captured records; their response/clipboard/storage failure mocks do not replace the production services.
- Real Chromium-based in-app browser: create synthetic assignment, upload PDF, inspect/confirm rubric, save notes, live search, save Su/Yang source, copy/read APA and MLA clipboard, manual checklist, JSON download, remove/restore/refresh, then assignment-only unlink while retaining the saved shelf. Download inspection confirmed rubric, notes and checked progress in the backup.
- Cross-tab browser test: after the first tab saved a note, the second displayed the stale-work alert rather than overwriting it.
- **Actual browser quota**, not simulated: a fresh loopback QA origin was filled until genuine `QuotaExceededError`. A growing 2,600-character note failed to save. Raw recovery export matched the fixture bytes exactly; attempted-change export contained the note. Removing only QA filler, Retry save and refresh restored the note. A queued-save/reload check retained two original assignments and did not persist the deliberately interrupted third assignment. This is reload interruption, not a physical disk failure, power loss or browser-process crash test.
- 320 px browser viewport: all three navigation items remained available; document width was 305 px with a 320 px viewport (scrollbar, no horizontal overflow). [Synthetic mobile evidence](local-readiness-mobile.jpg). Viewport was reset after testing.

## Reproduce locally without touching existing work

1. Use Node 24. From the checkout, run `npm test`, `npx tsc --noEmit --incremental false`, `npm audit`, and `npm run build`. Do not build into `.next` while running the development server from the same checkout.
2. For live checks, choose an unused origin: PowerShell `$env:QUILLORA_ACCESS_MODE='local'`, then `npm run dev -- --port 3027`. This binds `127.0.0.1`; do not expose it to a network. Confirm the address differs from the student's normal workspace. `$env:TEST_URL='http://127.0.0.1:3027'; node tests/integration.mjs` uses committed synthetic fixtures/public topics and does not refresh the corpus unless explicitly instructed.
3. In that test origin create an assignment, upload `tests/fixtures/rubric.pdf`, review/confirm and Save assignment details. Its fixture question differs from the AI topic intentionally: inspect/edit it yourself rather than expecting automatic compliance. Save a live source, copy both styles, check a requirement and add notes. Export backup; remove a source; import/merge the exact downloaded synthetic file; refresh and inspect the assignment. Repeat import to check duplicates/conflicts through the automated tests. Do not import student exports into the audit.
4. Test context protection: edit a saved assignment's notes/name; choose another assignment. Keep editing retains the draft; Save and continue persists; Discard edits and continue preserves the last saved version. Unconfirmed pasted rubric edits must block Save until reviewed. Start a delayed search and switch projects; the previous result must not appear in the new context (`tests/storage-ui.test.ts` makes this reproducible with controlled responses).
5. For **real quota** use a separate unused QA origin: `$env:QUILLORA_QA_PORT='3037'; node scripts/browser-recovery-harness.mjs`. Open `http://127.0.0.1:3037`, verify it is disposable, Seed disposable fixture (refuses to overwrite an existing seed), Continue research, enter a growing note, Fill actual browser quota and Save assignment details. Export stored data and attempted changes; verify baseline unchanged. Remove disposable filler only, Retry save, refresh, inspect notes. Queue disposable save and reload must not create `INTERRUPTED MUST NOT PERSIST`. Never run filler actions on the student's origin. The harness is not included in the production image.
6. Production denial smoke: after building, run Next on loopback port 3019 with no Access configuration, then `node tests/production-access.mjs`. Expect pages/APIs to deny with 503 and health to return only status. Valid signed-token unit tests are synthetic and require no provider credentials.

## Prioritized remaining gaps and readiness decision

1. **Academic review before student reliance:** independent MLA 9/APA review of the prepared difficult cases; article identifiers, long page ranges, group/partial author metadata, unusual punctuation and capitalization. Keep draft warnings until reviewed. Full handbook certification is not implied by tests.
2. **Real-world browser/accessibility coverage:** test a second engine and a real mobile browser, keyboard-only creation/upload/import flows and a screen reader; review text contrast. Current Chromium/320 px evidence is useful but incomplete. Test lock-unavailable environments, storage denial policies and actual process-crash recovery in disposable profiles before making broader recovery promises.
3. **Discovery/requirement limits:** source quality/type and relevance still need publisher/library checks. No verified OA/peer-review filter, automatic claim support or rubric-compliance engine exists. A future free integration should only be added for a specific evidenced need and must preserve unknown states; do not expand providers merely to increase the count. Pagination/server-side year refinement can be considered after a real student usability need is demonstrated.
4. **Persistence contract:** keep one browser profile/origin, deliberate saves and private exports. Unassigned drafts and unsaved pending form edits have no guaranteed crash recovery. Backups are plaintext, and importing into older software can lose new optional fields. Do not claim automatic server backup or cross-device sync.
5. **Maintainability, not a launch blocker by itself:** the existing compact Home component couples several flows. Focused tests now cover corrected paths; a later limited extraction into small components/hooks could help, but a broad rewrite is not needed to use the app locally.

No unresolved P0 data-loss/security defect was observed in the tested paths after these corrections. This is not a blanket security certification. Quillora is useful locally now as a metadata-based research desk and citation-draft aid. It becomes a candidate for private staging only after the academic/manual-browser gates above have acceptable results and the owner accepts the documented local-backup limitations. Hosting approval is neither requested nor implied in this milestone. Even then, hosted provider/security/resource checks would remain necessary before students.
